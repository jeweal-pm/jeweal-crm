# Changelog - 03 September 2026

## GIS Fair Funnel lead remarks

- Added an optional `remark` field to the public `POST /api/gis-fair-lead` payload.
- Limited remarks to 2,000 characters and retained the existing request sanitization for control characters.
- Stored the latest submitted remark on the associated `gis_fair_leads` record.
- Updated duplicate submissions for the same email and event to replace the lead's remark with the latest submitted value.
- Included `data.remark` in successful API responses.
- Displayed the remark in the Fair Funnel lead detail page for CRM users.

## Database

- Added the nullable `gis_fair_leads.remark` text column.
- Added the nullable `gis_fair_tracking_links.expired_redirect_url` field.
- Existing Fair Funnel leads remain valid and receive a `NULL` remark.
- Deployment requires `php artisan migrate --force` in production.

## Expired Fair Funnel redirects

- Added an Expired redirect URL setting to each Tracking URL create and edit form.
- Redirected visitors away from closed events, events not accepting submissions, expired offer periods, and unavailable tracking links.
- Treated an event's `ends_at` as the maximum lifetime for every tracking URL, even when a link has a later `expires_at` value.
- Used each tracking link's `expired_redirect_url` when configured and `https://jeweal.com` as the default fallback.
- Prevented expired redirects from creating tracking visits or increasing tracking-link click counts.

## Quality assurance

- Added API and persistence assertions for creating and updating Fair Funnel lead remarks.
- Added redirect coverage for configured event URLs, the default Jeweal fallback, and tracking exclusion.
