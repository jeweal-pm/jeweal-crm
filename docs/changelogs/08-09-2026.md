# Changelog - 08 September 2026

This release consolidates the CRM, email automation, WhatsApp security, and GIS Fair Funnel work delivered from 25 August through 8 September 2026.

## Email Automation And Sequences

- Added reusable email templates with HTML, plain-text content, preview text, sender settings, variables, versioning, publishing status, and safe variable rendering.
- Added configurable automation for customer confirmations, internal notifications, welcome messages, CC/BCC recipients, assignment recipients, and delayed delivery.
- Added test-send support from the template administration screens.
- Added reusable step-based email sequences with configurable templates, delay values, delay units, publish status, and sequence details.
- Fixed sequence step creation so adding a step does not submit the parent sequence form.
- Added sequence list and sequence enrollment management screens.
- Added manual enrollment, scheduled next-step processing, enrollment status tracking, and enrollment deletion for test subscribers.
- Manual enrollment now processes a due first step during the enrollment request; later steps remain scheduler-driven.
- Explicitly initializes new enrollments at Step 1 so the first message is not skipped by an in-memory model default.
- Added source-aware email sender resolution for General, GIS, and GMS enquiry types.
- Added GMS Fair and Jeweal Fair email template types to the email administration UI, validation, segment filtering, and sender resolution.

## Branded Fair Funnel Emails

- Added source-based email template selection for `POST /api/gis-fair-lead` and confirmation resends:
  - `gms_funnel` uses GMS Stone templates.
  - `gis-fair-funnel` uses GIS Fair templates.
  - `design_jeweal` and all other sources use Jeweal templates.
- Added customer confirmation and internal notification templates for GMS Stone and Jeweal using the GIS Fair email structure.
- Added GMS Stone branding with `https://gms-stone.com/image/logo.png` and the `#00453F` palette.
- Added Jeweal branding with the Jeweal logo and the `#1a1c4a` palette.
- Added branded automation configurations and seeded template records through `GisFairFunnelSeeder`.
- Added Fair lead remark/message fallback to the email context for internal notifications.
- Added source type options for Fair-specific email test sending.

## Enquiry Consent

- Added the same optional privacy policy and marketing consent fields to POST /api/gis-enquiry.
- Added the GIS Enquiry migration, model casting, API resource output, and regression coverage for the new fields.

- Added optional `privacy_policy_accepted` and `marketing_consent` fields to the general enquiry API.
- Added persistence, casting, request validation, API resource output, and feature coverage for the new consent fields.

## GIS Fair Funnel

- Added public Fair event configuration, tracking URL, attribution, lead registration, and redirect workflows.
- Added optional lead remarks with validation, persistence, duplicate-submission updates, API output, and CRM display.
- Added optional Tracking URL expiration and expired redirect URL settings.
- Applied the Event `ends_at` as the maximum lifetime of every Tracking URL.
- Added fallback redirection to the configured URL, or `https://jeweal.com` when no URL is configured.
- Added optional Tracking URL Fair Code prefixes with uppercase validation and persistence.
- Fair Codes now fall back to the Event code when a Tracking URL prefix is not configured.
- Set new Fair Funnel leads to `prospect` by default and migrated existing `lead_mql` Fair leads where appropriate.
- Added case-insensitive GIS Fair prefix matching for the unified GIS prospect workspace.
- Added public Fair lead source attribution and preserved separate submission/consent evidence.

## Unified GIS Prospect Workspace

- Extended `/gis-enquiry` to include direct GIS enquiries and eligible GIS Fair prospects.
- Added source filtering, Fair Code search, Fair Funnel remark display, assignment, status updates, reply, spam review, soft delete, restore, details, and mixed-model bulk actions.
- Added `/gis-fair/dashboard` with event, date, source, status, consent, business type, and country filters.
- Added registration, unique prospect, conversion, repeat submission, consent, lifecycle, source, country, and event comparison analytics.
- Kept spam and soft-deleted records out of management analytics.
- Added MySQL-compatible aggregation for installations using `ONLY_FULL_GROUP_BY`.

## Bulk Actions And Confirmation Dialogs

- Added row checkboxes and Select All controls to Jeweal, GIS, GMS, and GIS Fair lead lists.
- Added bulk delete, restore, assign, and status-change actions with permission and visibility checks.
- Added transactional processing and rollback protection for mixed or unavailable selections.
- Replaced browser confirmation prompts with a reusable centered confirmation dialog.
- Added keyboard Escape handling, backdrop dismissal, focus restoration, accessible labels, and action-specific styling.

## WhatsApp Delivery And Security

- Added `POST /api/whatsapp/messages` with E.164 phone validation and public-form handling.
- Added Twilio WhatsApp configuration with encrypted credential storage.
- Added configurable daily quota, retry attempts, retry delays, sender number, and timezone.
- Added Waiting, Complete, and Failed message administration screens.
- Added deletion for stored WhatsApp messages to support test numbers.
- Added lifetime duplicate-recipient protection for stored WhatsApp messages.
- Added scheduled waiting-message processing and retry handling.
- Added shared IP blacklist management and shared IP decision logging across WhatsApp and enquiry modules.
- Replaced file-based enquiry rate limiting with database-backed security services.

## Deployment And Verification

- Added and updated the GIS Fair, WhatsApp security, consent, and email management migrations and seeders.
- Updated CORS configuration, queue defaults, environment examples, local Docker services, permissions, and administration navigation.
- The latest source-based email routing change does not require a new migration, but production should run the Fair seeder to create or update the new templates and automation configurations.

Production commands:

```bash
php artisan migrate --force
php artisan db:seed --class=Database\Seeders\GisFairFunnelSeeder --force
php artisan optimize:clear
```

- The scheduler must run `php artisan schedule:run` every minute.
- A queue worker is required when `QUEUE_CONNECTION=database`.
- Latest verification: full Laravel suite passed **86 tests**; targeted GIS Fair Funnel coverage passed **15 tests**.
